### Findings (all P2, non-blocking)

**P2-1 — Empty-deletion-list input invariant is unenforced, so the frozen `INVALID_ARGUMENT` polarity degrades to `RETRY_REQUIRED`.**
`packages/storage/src/maintenance.ts:223`. The contract freezes "an empty deletion list is valid only when the expected floor parent is already that same no-head value", and requires impossible relationships to "fail before transaction work". `captureAheReclamationInput` validates identity disjointness and floor binding but never relates `deleteGenerationIds.length` to `expectedBaseExpectedHead`. Failure scenario: a request with `lineageFloor.deleteGenerationIds: []` and a *present* `expectedBaseExpectedHead` passes capture, enters `BEGIN IMMEDIATE`, walks a non-empty prefix, and fails `sameIds` at `:472` with `AHE_RECLAMATION_RETRY_REQUIRED` instead of `AHE_RECLAMATION_INVALID_ARGUMENT`. Safe direction (zero writes, no poison), but the wrong code and after transaction start. Smallest correction: inside the `:223` guard, add `(input.lineageFloor.deleteGenerationIds.length === 0) && !headsEqual(expectedBaseExpectedHead, replacementBaseExpectedHead)` → `invalid(...)`. `headsEqual` is already imported at `:5`.

**P2-2 — The Node two-live-handle control cannot interleave, so it proves idempotent replay rather than lock serialization.**
`packages/storage-node/tests/phase-6b-ahe-reclamation-red.test.ts:606`. `DatabaseSync` is synchronous and `reclaimClosedEpoch`'s only suspension point is `await Promise.resolve()` at `…/src/internal/ahe-reclamation.ts:123`, so `Promise.all([first…, second…])` runs the first transaction start-to-`COMMIT` before the second begins; `[0, 2]` is guaranteed by event-loop ordering, not by SQLite locking. The frozen invariant ("cannot combine old classification with new writes") still holds structurally because classification occurs inside `BEGIN IMMEDIATE`, and the Chromium control at `…entry.ts:242` *does* genuinely interleave two IDB connections. Nonblocking; if strengthened later, the honest form is a two-process control reusing the existing child fixture, not a re-ordered `Promise.all`.

**P2-3 — The browser fixture computes a facade-key census that no assertion consumes.**
`packages/storage-browser/tests/assets/phase-6b-ahe-reclamation-entry.ts:203` builds `facadeKeys`, but `packages/storage-browser/tests/phase-6b-ahe-reclamation-red.pw.ts:86` uses `toMatchObject` over a key set that omits it, so the browser side has no executable 12-key/no-13th-key assertion (only the memory facade is censused, in `tests/phase-6b-ahe-reclamation-red.test.ts:282`).
