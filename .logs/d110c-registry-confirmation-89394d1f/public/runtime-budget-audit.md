Bind corrected 29-entry roster and five variant environments; explicitly unset obsolete successor certification environment. Reviewers remain stopped during runtime stages.
2. **RED authoring, then static gates.** RED author writes only released test evidence. Capture the fresh selected-root strict compiler baseline after those files exist, before GREEN. Selected-root errors block RED acceptance/GREEN handoff. Execute the new RED whole file once under its frozen bounded budget; the expected existing-evaluator assertion must be reached. 3. **GREEN preparation, still no timing discovery.** Implement only reviewed GREEN scope. Before test collection, source/filesystem inspection confirms all current artifact/surface prerequisites, historical object availability and isolated built-closure availability. Preserve main built hashes. Do not call existing successor readiness to decide whether a retired authority is ready.
4. **One bounded readiness stage.** Once separately released, execute the five integrity-only child checks serially, then the new current-contract whole file, historical-only successor whole file, seal whole file, pacemaker whole file, and the two build-dependent whole files in the reviewed safe locations. These are full tests and can be the first seven test invocations of the GREEN main roster, not an unrecorded pilot plus an automatic rerun. Within the new suite each real-Git family proves unchanged-base acceptance before its negatives and reports exact statuses/outputs.
5. **Continue fixed main roster only after readiness passes.** Run registry-spec and remaining affected whole files/variants serially under their frozen limits, retaining all packaging, oracle, compiler, lifecycle and runtime-parity obligations. Collect discovered/executed/passed/failed/skipped/pending identities, collection time, per-test/child elapsed time, exit/signal, stdout/stderr, cwd/environment, and cleanup proof. All retained readiness cases must execute; zero skipped/pending is required. A test-runner count alone is not a child-readiness proof.

Keep main outputs unchanged. Then perform separately reviewed signed-checkpoint-to-working-tree root/v2 evidence; controlled repositories do not authorize the amendment under the obsolete base.
7. **Unexpected terminal result is a stop.** Timeout, skip, missing prerequisite, nonzero unexpected exit, ambiguous RED cause or remaining child process blocks continuation. Seal the first evidence and return to root for an explicitly changed, reviewed experiment; no automatic retry, longer ceiling, source patch, install, rebuild or campaign. A successful bounded readiness stage provides measured evidence for the exact frozen implementation only, not a general runtime claim.
