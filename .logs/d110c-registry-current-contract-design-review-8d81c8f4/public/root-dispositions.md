2. **Ed25519 and blueprint profile owners are active compound-hash consumers.**
   Root verified that both current script checkers pin the old root-policy hash,

   profiles, policies, vectors, contracts and tests must receive an explicit
   current disposition. Do not repin their root-policy hash while also placing
   them in that root policy's hash roster: that would be circular. The next
   design must make root governance own their custody and remove their duplicated
   root-state authority while preserving profile semantics.
3. **Historical live-hash tests extend beyond the initial map.** Root verified
   c2, d, d2 and b2b live-file hash loops. Keep their historical statements and
   semantic controls; explicitly supersede the current-path pin assertions.
   Retitle changed predicates rather than skipping these suites or editing old
   attestation hashes to claim new approval.
4. **Pacemaker readiness is an acceptance obligation.** Root verified its
   absent-base success and candidate-checker bootstrap cases. Require every
   readiness-blocked case to execute after repair; replace the bootstrap-success
   predicate with fail-closed missing/obsolete-base and unchanged-current-base
   controls, retaining drift/unprotected-owner/no-op-checker rejection. This is
   the same obligation already required for seal.
5. **Semantic source inspection must have an exact test seam.** The existing
   evaluator's hash map cannot prove schema or routing semantics. Freeze the
   source-bearing validation interface and its binding to captured hashes, or
   keep a precisely named separate semantic validator with its genuine callers.
   No missing export or generic stale-hash error can stand in for that coverage.
6. **Current lifecycle has eight exclusions.** Root verified the intentional
   current `**/.logs/**` exclusion beside the seven earlier entries. The exact
   current lifecycle and matching contract need explicit acceptance, preserving
   discovery of current suites and suppression mutations. Attribute a new RED
   refusal to its actual predicate; do not label lifecycle drift a measured
   optional-registry rejection.
7. **Registry version semantics require an explicit baseline statement.** The
   signed W0 registry retains version 1 while declaring version bumps for registry
   changes. The next design must state the chosen current baseline semantics and
   the prospective bump obligation, without pretending the old amendment obeyed
   the prior policy or changing runtime profile support implicitly.
8. **Checkpoint claims must reflect the amendment.** Preserve future host
   enforcement requirements but distinguish them from how this reviewed
   development baseline is established. Do not claim old-base workflow approval,
   branch-protection verification or installation in another protected branch.
9. **Dormant budget checkers need an explicit disposition.** Root verified their
   seven-field predicates. Fable distinguishes custody-only historical checkers
   from active execution; Grok flags the risk of leaving that distinction vague.
   Freeze each actual invocation/consumer and preserve semantic subsystem tests.
   No old checker may become a hidden alternate current authority.

The exact owner map, complete protected inventory, acyclic hash dependencies,
