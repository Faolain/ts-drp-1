# Residual ownership and allocation provenance

The first question is what the preserved heap-graph complement contains, not
which cleanup makes its slope smaller. Enumerate shallow bytes outside validated
current-database dominator subtrees and reconcile every signed interval delta.
Shared database-reachable objects may remain outside those subtrees; complement
membership is not evidence that an object belongs to product runtime state.

Reuse the existing offline ownership analysis. Keep historical reports immutable,
verify snapshot identity, process one graph at a time, and retain explicit unknown
buckets. Constructor names classify representation, not lifetime correctness.
Representative strong paths explain owners but do not replace exhaustive byte
accounting. Check sum conservation, shared payloads, negative deltas and rejected
overlapping anchors before accepting any attribution. Independently review the
ledger and root evidence before changing lifecycle behavior.

Only if allocation provenance remains material, validate a worker-local inspector
instrument on a small retained/released allocation control. Sampling gives stack
leads, not exact object identity. Allocation tracking can provide trace IDs only
for allocations observed while tracking was active. Neither retroactively adds
stacks to the existing snapshots, nor proves lifetime violations alone.

The existing profiler owns any eventual recorder: session, bounded scalar phase
markers and files, never workload objects or historical promise/error references.
Keep sampling/profile output out of measured GC frames. Test source locations,
post-GC survival, cleanup on failure, missing native/code coverage and artifact
bounds before connecting to the shared workload. Optional lifecycle counters
belong only at evidence-backed seams; universal call wrapping is out of scope.

One targeted workload capture is conditional on a concrete unanswered allocation
question. Declare its window, output/runtime bounds and discriminating outcome
before launch. Preserve the workload, assertions, startup settlement, identities,
retention policy and default heap. Do not launch another full100 campaign merely
to reproduce aggregate growth. Any confirmed lifetime defect requires independent
RED/GREEN ownership; absent that proof, report uncertainty without cleanup.

Primary references: [Node inspector](https://nodejs.org/download/release/v22.15.0/docs/api/inspector.html),
[V8 HeapProfiler](https://chromedevtools.github.io/devtools-protocol/v8/HeapProfiler/),
and [Node V8 statistics](https://nodejs.org/download/release/v22.15.0/docs/api/v8.html).
The pinned runtime control, not the latest protocol's optional fields alone,
determines which signals are actually available.
