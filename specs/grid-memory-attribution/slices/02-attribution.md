# Retaining-owner attribution

Compare constructor counts and shallow sizes, dominator retained sizes and
representative strong root paths between worker snapshots. Use an established
heap graph implementation or validate graph semantics before trusting retained
sizes; weak edges and overlapping subgraphs must not inflate attribution.
Analyze outside the workload worker. Add bounded allocation sampling only when
retainers leave the allocation origin unresolved.

Classify evidence as intentionally persisted fake-IDB data, harness retention,
product lifecycle violations, or unresolved growth. Storage logical bytes are
supporting content telemetry, never a numerical heap correction. A suspected
owner requires a root chain and violated lifetime contract before cleanup.

The artifact is a compact evidence-backed report with representative node IDs,
paths and deltas; unresolved categories remain explicit. Review that causal
report before creating owner-specific RED/GREEN tasks.
