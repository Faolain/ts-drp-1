# Completion proof survives physical source drain

A committed source can be settled while its exact native issued/outbox pair still exists. Publication may remain pending, or an independent earlier row may block the physical prefix. The bounded completion proof must remain available through that interval, including cold reopen and unrelated FENCE or settlement-plan progress. A metadata rewrite that drops the proof merely because the source is eligible to retire confuses intended deletion with actual absence.

Proof custody and physical protection therefore have different jobs. Retaining a terminal completion entry and its contexts preserves classification of the native source. That proof-only reference does not, by itself, create a protected hole. The original pruning owner may remove an otherwise eligible exact pair; a later fresh metadata rewrite removes its terminal entry after authenticated native absence. Ordinary fences, replacement dependencies, pending publication, and other consumers retain their existing protection rules. This distinction does not relax them.

The adjunct in [`source-proof-drain.qnt`](../../../../packages/protocol-v3/formal/source-proof-drain.qnt) follows two exact committed sources sharing a completion context and an independent blocked prefix. An original publication ACK discharges the pending outbox consumer; inclusion alone does not. Physical pruning changes the native pair and watermark together without erasing its proof. Metadata rewriting projects the surviving source references from a fresh native image. The shared context remains whole until the last entry releases it, so draining one source cannot strand its pending sibling. Cold reopen clears runtime read evidence and reconstructs classification from the durable state.

## An old before-plan is not a current proof owner

The regression control drops an eligible source entry before physical drain and retains a genuine old before-plan tied to one exact rewrite target. That inverse temporarily reconstructs the lost proof only while the current plan equals that target. Independent legitimate plan progress changes the target identity. A subsequent reopen then lacks a current source proof even though the exact native pair remains. Accepting the old before-plan after that change would widen historical data into current authority.

The safe lifecycle never uses an inverse helper. Its negative control records the identities actually used by an accepted read; the authority assertion compares that decision-time evidence independently of the acceptance guard. A separate small projection checks exact-target acceptance and rejection across plan progress. A read that was valid before progress remains a historical event, not permission to read or delete again afterward.

## Correspondence and limits

The intended implementation owner is the existing issuance retirement pipeline. `issuanceRetirementTargetRows` retains terminal proof-bearing entries while `retirementLocalSource` finds the exact native source. `issuanceRetirementImage` authenticates complete pair identity. The original protection closure remains separate, and `assertPreparationRows` continues to require ordinary dependencies to be protected. Native SQLite/IndexedDB prefix pruning removes the pair atomically; only a later original metadata rewrite observes its absence and releases unreferenced contexts. The implementing recovery change is still in progress at this model snapshot, so final source correspondence and native evidence remain a separate gate.

Every modeled source id denotes the full object/author/sequence/digest identity, not a sequence number alone. Authentic completion inclusion, signed Cut/QC/trust, complete issued/outbox pairing, truthful unfiltered census, original held native currency, protected-hole checks, and atomic native effects are premises. Exact plan identity has no ABA or collision in this projection. The model does not prove those premises or implement their cryptography.

The lifecycle has two sources, one shared context, one independent prefix blocker, and one unrelated plan-progress event. It checks custody and constructive release paths, not fairness or eventual network publication. A permanently pending ACK may legitimately retain its row and proof. Explicit author expiry requires a separate authenticated cancellation of the retry consumer and is outside this committed-source adjunct. Context presence is abstract; canonical byte reserves and proof-size bounds need native capacity evidence.

The exact-target projection's finite arbitrary-state base and one-step checks apply only to its recorded identity fields. They do not prove the whole lifecycle inductive, unbounded plans or sources, TypeScript/native refinement, crash durability, or composition with all previous models. Earlier rejoin, replay, and pending-floor evidence keeps its original scope; no counts are combined into a larger theorem.

The source-hashed registry [`check-source-proof-drain.mjs`](../../../../packages/protocol-v3/formal/check-source-proof-drain.mjs) owns the executable checks and expected counterexamples. [Archived evidence](evidence/source-proof-drain) binds those inputs to raw logs. Nonvacuity controls exercise partial and final release; mutation controls require actual verifier violations for premature proof loss, stale inverse authority, shared-context loss, and pending-pair erasure. A timeout or checker error is never a passing negative control.

With installed Quint, Apalache, and Java 17, run `node packages/protocol-v3/formal/check-source-proof-drain.mjs all`. The registry accepts `test`, `verify`, and `induction`; `SOURCE_PROOF_LOGS`, `SOURCE_PROOF_ENDPOINT`, and `SOURCE_PROOF_CASE_FILTER` select the evidence directory, unused checker endpoint, and explicitly partial reruns. The existing watchdog owns and reaps each checker process group.

The [independent review](evidence/source-proof-drain/independent-review.json) found no actionable defects, reproduced the complete check registry, and verified final and superseded evidence hashes. Its repetition preserves the same bounded claims and does not close the production correspondence gate.
