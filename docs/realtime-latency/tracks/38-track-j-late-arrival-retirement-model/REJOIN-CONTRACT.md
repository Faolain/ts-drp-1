# Rejoin, actual recovery roles, and unresolved source custody

A signed remote point establishes target snapshot authority. It does not turn the remote predecessor into a locally published generation or say whether an older local operation committed. This adjunct separates checkpoint attachment, actual native recovery roles, unresolved-source custody, and current deletion authority so each distinction has a small finite state space and its own negative controls.

The reproducible registry is [`check-rejoin-contract.mjs`](../../../../packages/protocol-v3/formal/check-rejoin-contract.mjs). Its archived [evidence](evidence/rejoin-contract) binds model and runner sources to raw checker results. An expected negative control passes only on a checker counterexample; translation errors, timeouts, and process failures are incomplete checks. The implementation hashes identify inspected sources, not a machine-checked refinement from TypeScript or native storage to Quint.

The final registry has evidence for all 58 checks and 54 directed test declarations: a complete 57-case batch followed by a 23-case rerun of the changed head/role source and its shared projection. Every selected model-file/watchdog hash matches the final sources. Seven finite safety graphs complete, six scoped Apalache base/step obligations pass, and all 38 expected mutation or nonvacuity counterexamples occur. The largest role graph has 2,335,818 distinct states and no queued states; it completes within the per-check bound. These counts describe the separately scoped obligations below.

## Remote proof and local history have different jobs

[`rejoin-head-roles.qnt`](../../../../packages/protocol-v3/formal/rejoin-head-roles.qnt) treats the complete signed remote predecessor-to-target transition, QC, ACLs, settlement predecessor, snapshot, and fixed genesis as an authenticated input. Attachment binds that proof to the actual local native head and revision. A prepared read may become stale before acquiring the original native writer; publication refuses unless the captured local identity remains current. Only tentative preparation can be abandoned in this model. Once the checkpoint receipt is durable, old-source Writer admission stays halted. A crash clears runtime verification authority; the original receipt owner may recover that authority before a complete candidate exists, then stage and finish publication while admission remains halted. The model includes this receipt-only boundary and rejects restoring old issuance during discovery. One durable receipt owns its immutable target: a competing higher-epoch offer cannot replace it, coexist as a second active intent, or change which original target cold recovery finishes. During the native floor/publication interval, external mutation is excluded by the original owner. The durable floor can describe the old state, a pending old-or-new publication, or the committed new state. Activation follows floor completion. A removed writer may reopen to read but cannot sign ordinary work.

The recovery window follows the actual native parent twice. A local publication sequence ending in 2, 4, 8 therefore yields usable snapshot roles 8/4/2; the remote proof of 7→8 grants no role to 7. Genesis is a trust pin and is excluded from usable rollback sources. Extra authenticated generation headers may remain within the admission bound without acquiring a usable snapshot or operational replay role. The finite graph accepts ordinary adjacent, checkpoint-gap, and promoted points in one local history, including a directed 0→1→3→5 cold reopen. It does not assume every retained generation has checkpoint-gap syntax. Both rollback choices may feed the original forward-promotion owner, which must publish a fresh epoch beyond the current floor. A valid historical signature alone cannot reactivate the old signing epoch.

Oldest-parent normalization is a permitted abstract cleanup action. It preserves the current and first rollback birth edges and the independently authenticated oldest point. A directed schedule normalizes that point, cold-reopens before any next floor begins, and retains the same usable window. This is a model law, not a claim about which specific generation a native test normalized. The contemporaneous native report observed roles 12/10/8 before the next floor and 14/12/10 after reopening an already staged successor; it had not yet identified whether the normalized positive point was the oldest usable role or an additional retained header.

The bounded graph includes every strictly increasing local target in its declared epoch domain. Integer epochs stand for exact local publication identities, with one published identity per epoch in this projection; conflicting same-epoch closures and cryptographic fork verification are outside it. The role projection separately checks an arbitrary-state base/one-step obligation over the three ordered publication slots. That projected induction does not establish receipt authentication, arbitrary unbounded integer domains, or refinement of the concrete role reader.

## Unknown does not mean omitted

[`rejoin-unknown-custody.qnt`](../../../../packages/protocol-v3/formal/rejoin-unknown-custody.qnt) gives each accepted source a hidden application truth: it may already have committed remotely or may have been omitted. Both remain observationally unknown until exact signed settlement evidence or explicit author disposition resolves local custody. Positive evidence has a distinct identity set; observing the application projection or another source’s settlement cannot classify this source. The zero-source receive-only path creates no custody plan obligation and may later become a writer. Gap length, removal, readmission, and cold reopen cannot choose a disposition or replay non-idempotent work automatically.

Acceptance reserves capacity for later source custody and disposition work. Before losing the old live anchor through a jump, each retained source must acquire its exact authenticated context in the existing bounded issuance plan. The context abstracts signed anchor, ACL, canonical parameters, and blueprint/ABI identity. It does not assume the executable historical ABI remains available. An unavailable interpreter must not erase unknown custody or infer a result. The finite model uses abstract units; actual canonical byte bounds and native plan accounting remain implementation obligations.

Explicit expiry is an author decision to abandon further local retry/resolution of an exact unknown source. It is a separate local-author signed disposition bound to the genuine current floor, not an ordinary application operation or a current Writer grant. It may be requested while that author is removed. In both hidden realities, expiry preserves the application projection; it does not undo an operation that committed remotely and does not mint a noncommitment proof. A previously sent operation may also arrive remotely after expiry; that legitimate later effect is preserved. The native/capsule consumers still join before source erasure and quota release. The per-source induction projection preserves accepted-source custody and this separation between epistemic status and application truth.

At the inspected implementation snapshot, explicit expiry was still pending. Its model is a required contract with negative controls, not evidence that a product expiry API already implements it. The eventual signed producer, replay verification, capacity reserve, cold recovery, and both hidden-reality product controls need their own implementing commit and native evidence.

## Absence evidence never owns current deletion

[`rejoin-pruning-currency.qnt`](../../../../packages/protocol-v3/formal/rejoin-pruning-currency.qnt) requires the original held native read, exact head/floor, complete census, independently derived current partition, matching current plan intent, and joined last consumers at deletion. A plan captured before a release/reacquire gap can become stale through head, floor, role, or intent change. Holding a native writer excludes incompatible mutation; yielding does not transfer authority or convert an old plan into a fresh one.

An absence receipt binds an immutable native publication tuple, anchor, and genesis. Mutable ancestry pointers are deliberately excluded. Historical reuse still requires an independently authenticated retained basis and a fresh current partition that already classifies that exact scope as absent. The receipt cannot classify a present, protected, or foreign scope and cannot excuse missing current protected material. The immutable-binding projection proves only that ancestry normalization frames this receipt identity; it does not prove native receipt authenticity or complete physical census.

## Implementation correspondence and applicability

The source snapshot manifest is the authority for inspected hashes and commit status. The main ownership mapping is:

| Abstract boundary | Implementation owner | Remaining premise |
| --- | --- | --- |
| Remote authenticated point and exact local attachment | `openCreatorCheckpointPoint`, `openCreatorCheckpointAttachment`, and `inspectCreatorCheckpointTransition` in `creator-transition-advance.ts` | Cryptography, complete carrier checks, nominal capability provenance |
| Floor prepare/publication/commit/activation | `creator-adoption.ts`, `creator-adoption-commit.ts`, `creator-adoption-activate.ts`, and the original room-head owner | Native CAS and crash recovery implement the old-or-new states |
| Three actual usable roles and historical absence bases | Original native checkpoint role reader in `creator-transition-advance.ts`; `captureSnapshotRetirementInventoryState` in `creator-closed-rollback-data.ts` | Complete native census, exact birth receipts, current classification and original joined ownership |
| Durable accepted-source context | `retainCreatorAcceptedSourceCustody` in `v3-live.ts`, `creator-source-custody.ts`, and the existing issuance plan | Exact signed context, current floor, authenticated parameter digest/schema, canonical byte accounting |
| Explicit author expiry | Required contract; producer not yet mapped | Exact author/source/floor signature, admitted reserve, cold verification and final consumer release |
| Forward promotion | Original forward-promotion owner and usable role source selection | Native product evidence for both actual rollback choices |

The responsiveness work yields between census rows and joined preparation stages while keeping original native holds and checking currentness on resume. A later retirement checkpoint is before original acquisitions and is restricted to no active room transaction, a stable floor with no pending transition, and no inherited-classification frame. The model allows captures to become stale before reacquisition and treats held native exclusion as a premise. It does not prove responsiveness, maximum event-loop gaps, or the implementation's placement of every await. Begin/publish/commit/activate/rebind remains one original transition ownership interval in this abstraction.

### Prior replay evidence is not repinned into a new theorem

The [replay applicability audit](evidence/rejoin-contract/replay-applicability.json) compares the prior replay-model commit with integrated baseline `7b5a6a57`. The prior model/runner inputs and directly inspected replay phase, borrowed-header, pool, and broadcast owner functions are unchanged. Their archived results remain results for those exact models. Identical function text alone does not establish unchanged behavior through every dependency.

The integrated common capacity change updates exact retirement-intent selection, interrupted active-intent reconstruction, journal-observation comparison, readiness-gate completion, and SQLite quote currency. The previously modeled positive same-intent/source law now has an implementing common change, including the distinction between exact active retry and fresh same-floor selection. The readiness model's nonempty terminal proof and joined release remain required before ordinary admission resumes. The SQLite no-plan/no-effect optimization starts from a fully authenticated image and checks same-connection counter/control/pending currency across both writer gaps in `NodeIssuanceImplementation.#transactIssue` (the separate `#withNativeSignAdmission` method is unchanged); the abstract quote model does not establish SQLite counter semantics or numerical sizing.

Pending-bootstrap turnover changes dependency classification: the independently authenticated pinned-genesis pair remains charged and protected before publication acknowledgement. That supports a census premise; it is not represented by a new replay state or proven by the old replay checks. The common native crash/mutation and bootstrap tests remain separate implementation evidence. The prior 59-check manifest is preserved unchanged; it has not been relabeled as verification of the newer production tree.

Full-contract arbitrary-state induction remains open. These finite graphs and scoped projected base/step checks do not prove composition of all writers, rows, arbitrary gaps, quota bytes, application operations, native crashes, and scheduler interleavings. No new result upgrades the earlier adjacent-install bridge to cover this public gap/manual-preserve path.

Independent review found no actionable defects, reproduced all 54 directed test declarations and six selected TLC checks, and checked the archived source/log hashes. Its [review record](evidence/rejoin-contract/independent-review.json) distinguishes those fresh checks from the retained complete evidence.

## Reproduce

With installed Quint 0.32, Apalache 0.56.1, and Java 17:

```sh
node packages/protocol-v3/formal/check-rejoin-contract.mjs all
```

`REJOIN_LOGS` selects the output directory, `REJOIN_ENDPOINT` selects an unused local checker endpoint, and `TRACK_J_TIMEOUT_SECONDS` sets the per-check watchdog. The registry supports `test`, `verify`, and `induction` for targeted reruns. A full run checks the complete registry. `REJOIN_CASE_FILTER` permits an explicit affected-case rerun; such a run is not described as a new full run. The final evidence manifest may compose an earlier full batch with a targeted rerun only when every selected case’s checked model-file and watchdog hashes match the final sources, and the complete final registry is covered. Each original run and runner hash remains preserved. The existing watchdog owns and reaps each checker process group, including JVM descendants.
